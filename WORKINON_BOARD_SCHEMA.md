# workin On Board Schema

As of Monday, August 24, 2026. Supersedes the August 2 card model.

## Goal

Show `MasterIndex` in `workin On` as an operational dashboard, not as a full
browsing experience. The web page remains the deep-dive surface.

`workin On` answers one question: **what needs a decision or an action now?**

## Source

`workinon/board-feed.json`, generated by `tools/generate_workinon_feed.py`
from `current/attention.json`.

The feed no longer decides what is important. That decision lives in
`tools/generate_attention.py` and its tuning rules, so the `workin On` tab and
the web page always agree. See `ATTENTION_BOARD.md` for the full model.

## Card shape

```json
{
  "id": "gap-peerlink-source-missing",
  "type": "open-gap",
  "entityId": "pickledballs-app",
  "title": "PeerLink source is missing, so PickledBalls cannot be built here",
  "body": "PickledBalls project.yml now links a local PeerLink package at ../peerlink ...",
  "action": "Locate or recreate the PeerLink package and restore it at ~/peerlink, or repoint PickledBalls project.yml at a resolvable source.",
  "priority": "high",
  "lane": "Needs Attention",
  "sortDate": "2026-08-13",
  "tags": ["gap", "local-path-missing"],
  "deepLink": "site/index.html?entity=pickledballs-app",
  "statusKey": "masterindex.open-gap.gap-peerlink-source-missing"
}
```

`action` is the field that makes a card worth showing. Render it — a card
without a visible next step is a log entry.

## Card types

`commitment`, `open-gap`, `link-gap`, `overdue-task`, `changed-since-review`,
`triage`, and a single `summary` digest card. Types are defined in `ATTENTION_BOARD.md`; this
file only governs presentation.

## Lanes

1. `Shipping` — dated release commitments, soonest first
2. `Needs Attention`
3. `Due Soon`
4. `Recent Activity`
5. `Summaries`

`Shipping` leads because release dates are what the board is opened for.

If lanes are unavailable, sort by lane order, then priority, then `sortDate`.

## Priority

Set by the generator, not by `workin On`:

- **high** — blocks a release, a build, or production correctness
- **medium** — a real gap or a pending decision with no immediate block
- **low** — informational, or a change awaiting review

## Status keys

Keys are namespaced `masterindex.<type>.<id>` and are stable across
regenerations, so `workin On` should upsert on the key rather than appending.
A card that disappears from the feed has been resolved and its status item
should be cleared.

## Deep links

Every card that concerns an entity carries
`site/index.html?entity=<entityId>`. That query-parameter form is the web
browser's supported contract; the older `#<entityId>` fragment form is not.

## What should not go into workin On

- the full repository table
- all cluster notes
- resolved or accepted gaps
- long narrative descriptions
- one card per recently-changed entry

That belongs on the web page.

## Expected volume

The board should stay small enough to read in one glance. If it grows past
roughly twenty cards, that is a signal to tighten
`current/attention-policy.json`, not to add scrolling.
